# Уроки проекта витрины

Собираю сюда то, что узнал на своих ошибках и удачах, чтобы не
наступать дважды. Новое - сверху.

## 16.11 - Яндекс CDN и статический сайт на своём домене

- **customServerName не сработал.** Стандартная схема «один бакет +
  CDN подменяет Host» у Яндекса не применилась почти 2 часа (ошибка
  NoSuchBucket от S3). Рабочая схема: бакет называется как домен
  (www.vadimsait.ru) + опция CDN forwardHostHeader. S3 сайт-режим сам
  находит бакет по Host заголовку. Адрес без www - отдельный бакет
  с редиректом на www.
- **Изменения в CDN применяются не мгновенно.** Патч конфига - потом
  обязательно purge кэша (`yc cdn cache purge --all`) и проверка
  curl-ом, а не «на глаз».
- **Файлы в бакет заливать с ACL public-read.** Без него объект
  закрыт: сайт целиком работает, а новая страница отдаёт 403.
  Поймали на pakety.html и странице-подсказке apex.html.
- **Адрес без www у reg.ru** делается A-записью на IP раздачи
  (188.72.112.1), а не платным «веб-форвардингом» reg.ru - тот без
  HTTPS и за 120 ₽/год.
- **Сертификат Яндекса** выпускается за ~10-15 минут после того, как
  CNAME _acme-challenge появился в DNS. Проверка: nslookup -type=CNAME.

## 15.11 - работа с Вадимом через телефон

- **Из чата на телефоне нельзя копировать.** Всё, что Вадиму нужно
  вписать куда-то, выкладывать страничкой в бакет с крупными
  копируемыми полями (как dns.html / apex.html).
- **Скриншоты - главный канал диагностики.** Инструкции давать по одному
  экрану за раз, «куда жать» - с подтверждением скрином.
- **Правило «покажи, потом публикуй»** действует всегда; исключение -
  технические страницы-подсказки, они не часть сайта.

## 15.11 - Vercel и блокировки

- Зарубежные хостинги (Vercel, частично GitHub) режутся российскими
  провайдерами плавающе: утром работает, днём нет. Для бизнес-сайта
  в РФ - только российское облако + свой домен.
- Проверку сайта «снаружи» делать внешним сервисом, с ноутбука видно
  не то, что видит клиент.
